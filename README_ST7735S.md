# OV2640 + 1.8寸 128x160 ST7735S(SPI) 显示工程

摄像头 OV2640 采集 → CH32V307 的 DVP → 取画面 → **分片刷屏** → SPI 送给 ST7735S。

工程只保留三个功能：

| 功能 | 说明 | 代码位置 |
|---|---|---|
| **① 摄像头出图** | 实时画面，全屏显示，**分片连续刷新**（无瀑布/撕裂，延迟小） | `main.c` 的 `DVP_IRQHandler()` + `LCD_PushBlock()` |
| **② 参数诊断页** | 帧率/行数/丢行/FIFO/清晰度/数据样本/时钟档位，上电自动显示几秒 | `main.c` 的 `LCD_DiagShow()` |
| **③ 像素校准画面** | 彩条 + 灰阶 + 黑白块 + 边框，用来校准颜色和显存偏移 | `main.c` 的 `LCD_CalibScreen()` |

另外有两组**纯宏开关**，不用改代码结构就能调：

| 开关组 | 位置 | 内容 |
|---|---|---|
| **画面显示开关** | `lcd.h` | `LCD_ROTATE`(0/90/180/270)、`LCD_MIRROR_H`、`LCD_MIRROR_V`、`LCD_INVERT`(补色)、`LCD_BGR_SWAP` → 见第六节 |
| **摄像头/延迟开关** | `main.c` | `OV2640_CLKRC`(帧率)、`CAM_FULL_VIEW`(视野)、`CAM_MIRROR_X`、`CAM_BYTE_SWAP`、`OV2640_AEC_VALUE`/`OV2640_GAIN_VALUE`(亮度) → 见第五、七节 |

> ⚠️ **下载前必须先做一步**：用 WCH-LinkUtility 把芯片配置改成
> **FLASH-192K + RAM-128K**（见第四节）。分片缓冲要 40KB RAM，而且栈指针放在
> RAM 顶部；出厂默认只分配 32KB。没配的话屏幕会显示 `RAM NOT 128K !` 并停在那里。

## 一、接线

### LCD（1.8寸 128x160 ST7735S，8 脚 SPI 模块）

| 模块 | 接到 | 说明 |
|---|---|---|
| GND | GND | |
| VCC | **3.3V** | 不要接 5V |
| SCL | **PB13** | SPI2_SCK |
| SDA | **PB15** | SPI2_MOSI |
| RST | **PC4** | 复位 |
| DC | **PB14** | 命令/数据 |
| CS | **PB12** | 片选 |
| BLK | **PC5** | 背光，高电平亮（也可直接接 3.3V） |

### 摄像头 OV2640

```
D0--PA9    D1--PA10   D2--PC8    D3--PC9    D4--PC11   D5--PB6    D6--PB8    D7--PB9
D8--PC10   D9--PC12   D10--PD6   D11--PD2
DCLK--PA6  HREF--PA4  VSYNC--PA5
SCL--PB10(SCCB)   SDA--PB11(SCCB)
RESET--PC13       PWDN--PC3      模块上的 NC 脚悬空不用接
```

### 串口

UART1(PA9/PA10) 被 DVP 的 D0/D1 占用，调试打印走 **UART2(PA2, 115200)**；
工程里已定义 `DEBUG=DEBUG_UART2`。没定义也不会出错（`DBG` 自动失效，不会卡死）。
接线要 **PA2 → USB-TTL 的 RX**，并且 **GND 共地**，否则看到的就是乱码。

## 二、上电流程与三个功能

```
上电
 ├─ ① 像素校准画面   (~2 秒)   彩条/灰阶/黑白块/边框
 ├─ ② 参数诊断页     (~6 秒)   各项统计 + 数据样本 + 时钟档位
 └─ ③ 摄像头实时画面 (全屏，一直跑)
```

### ① 像素校准画面怎么用

| 检查点 | 现象 | 改 `lcd.h` |
|---|---|---|
| 8 条彩条颜色是否正确 | 红蓝对调 | `LCD_MADCTL` 在 0x00/0x40/0x80/0xC0 上加 0x08 |
| 白的地方是否发黑 | 像底片 | `LCD_USE_INVON` 0 ↔ 1 |
| 四周白边框是否完整 | 少一行/多一列、画面偏移 | `LCD_XSTART`（试 2） / `LCD_YSTART`（试 1） |
| 8 条彩条是否等宽 | 不等宽说明水平不是 1:1 | 一般是 SPI 时钟太高：把 `LCD_SPI_PRESCALER` 换 `SPI_BaudRatePrescaler_8` |
| 灰阶是否平滑 | 有断层/跳变 | 一般是接线或供电问题 |

> 校准画面也是走"分片刷屏"这条路（一条条推给屏），所以**校准画面正常就说明刷屏链路正常**。

### ② 参数诊断页怎么读

（行距按屏高自动均分，竖屏/横屏都排得下；最后一行是**当前画面开关的状态**，拍照发人看时很有用）

```
-- DVP DIAG --
fps:16 r/s:5120     每秒帧数 / 每秒行数  ← 帧率指标, 直接反映"延迟感"
f:23 r/f:320        累计帧数 / 每帧行数 —— 必须是 320
drop:0 clk80        丢行次数 / 摄像头时钟档位(OV2640_CLKRC)
flex:0 foc:823      DVP FIFO 溢出(必须 0) / 清晰度(越大越锐)
e:132 o:16          行缓冲偶/奇字节平均值(判断像素格式)
41 3F 55 62 ..      行缓冲0 前 6 字节(应随画面变化)
A1 0C 78 33 ..      行缓冲1 前 6 字节
128x160 of 240x320  屏尺寸 / 摄像头输出尺寸(1:1 中心裁剪)
rot0 mh0 mv0 iv0 bgr0   旋转/左右镜像/上下镜像/补色/红蓝互换 的当前开关状态
```

| 现象 | 结论 | 处理 |
|---|---|---|
| `fps` 只有 4 左右 | 摄像头时钟档位太慢 | 见第五节：`OV2640_CLKRC` 改成 `0x00` 或 `0x80` |
| `drop` 一直涨 | 推屏/中断跟不上（分片被改写所以丢行） | 把 `LCD_SPI_PRESCALER` 换成 `SPI_BaudRatePrescaler_2`（24MHz），或把 `SLICE_ROWS` 调大 |
| `flex` 不为 0 | DVP FIFO 溢出 | 降低 `OV2640_CLKRC` 档位，或调大 `OV2640_PCLK_DIV` |
| `r/f` 不是 320 | 摄像头输出尺寸/降采样档位不对 | 确认 `OV2640_READOUT_OPT = 0` |
| `f` / 行缓冲都为 0 | 摄像头没输出或没同步 | 查 DCLK/HREF/VSYNC 接线、3.3V、SCCB |
| `f` 为 0 而 `r/s` 在涨 | VSYNC 没接好 | 查 VSYNC→PA5 |
| 两行十六进制一直是 00 | 数据线没接对 | 逐根核对 D0~D7 |
| 画面糊、转镜头时 `foc` 有明显峰值 | 镜头失焦 | 转到峰值位置；拧不动/转到底仍糊就是模块问题 |
| 屏上多出一块固定花边/文字跑到屏幕外 | 画面开关（旋转/镜像）用错了 | 见第六节，改 `LCD_ROTATE` 时`LCD_XSTART/LCD_YSTART` 可能要跟着微调 1~2 |

### ③ 摄像头实时画面

全屏显示，两种取图方式（见第七节）：默认**中心 1:1 裁剪**，可切换成**全视野 2:1 降采样**。

## 三、数据通路（为什么没有瀑布/撕裂）

```
DVP 收一行 ──中断──> 交换字节序(可选镜像/缩放) ──> 写进"片"(10 行一条)
                                                      │ 攒满一条
                                                      ▼
                                      主循环立刻用 SPI+DMA 把这条推给屏
```

* **最早的做法（一行行推）**：每行都要 CPU 一个个字节挪进 SPI，一行约 190µs，
  赶不上摄像头出行的速度 → 丢行、画面被"擦"过去（瀑布感）。
* **后来的做法（整帧双缓冲）**：一帧 40KB 在 RAM 里攒满，再整屏瞬刷。
  瀑布/撕裂没了，但**屏上的内容平均要老半帧**（4fps 时就是 125ms 的额外延迟），
  而且画面是"一下子跳一帧"。
* **现在的做法（分片刷屏）**：把画面切成若干条、每条 10 行(竖屏 16 条 × 2560 字节)，
  **攒满一条就立刻 DMA 推走**，所以：
  * 屏上是连续更新的（不会一跳一跳）；
  * 刚采到的那几行几十毫秒内就上屏，**显示的永远是最新内容**；
  * DMA 搬运不占 CPU，CPU 只负责"攒行 + 启动 DMA"；
  * RAM 只要 40KB（整帧双缓冲要 80KB）。旋转 90/270 变成横屏时是 13 条 × 3200 = 41.6KB。

一条片刷进去只要 2560×8 ÷ 24MHz ≈ **0.85ms**，远小于面板扫 10 行的时间(1.04ms)，
所以既不会撕、也不会和面板打架。

> 画面本身的旋转/镜像/补色是用面板寄存器做的（第六节），**不经过这条数据通路**，
> 所以既不花时间也不占 RAM。

## 四、RAM 配置（**第一次使用必做**）

分片缓冲 40KB + 行缓冲 1KB + 其它 ≈ **43KB**，而且栈指针在 RAM 顶部：

| 配置 | RAM | 本工程 |
|---|---|---|
| FLASH-192K + RAM-128K | 128KB | ✅ **需要这一档** |
| FLASH-224K + RAM-96K | 96KB | 也能跑 |
| FLASH-256K + RAM-64K | 64KB | ❌ 栈会跑到不存在的地址 |
| FLASH-288K + RAM-32K | 32KB | ❌ 出厂默认，不够 |

**操作**：WCH-LinkUtility → 连接芯片 → `Target`/`Config` 里的 FLASH/RAM 分配 →
选 **192K/128K** → 写入配置（会重新擦写芯片）→ 再用 MounRiver 下载本工程。

工程自带的 `Ld/Link.ld` 已按 128K 写好（不再使用共用的 `SRC/Ld/Link.ld`，避免影响其它例程）。
配置没改成功时，程序启动会自检并在屏上显示 `RAM NOT 128K !`。

## 五、帧率与延迟（**"画面延迟大"的真正原因**）

### 1. 延迟由三块组成

| 来源 | 大小 | 说明 / 处理 |
|---|---|---|
| **① 摄像头一帧的时间** | **60~250ms** | ❗**大头**。由 `OV2640_CLKRC` 决定（见下面第 2 条）。 |
| **② 攒帧/搬运** | **~5~15ms** | ✅ 已用"分片刷屏"压掉（原来是整帧攒满才刷，白等半帧） |
| ③ 面板自身扫描出图 | ≤16.7ms | ❌ 屏固有（60Hz），**不是瓶颈**，改不了也不值得改 |

**所以"延迟大"不是屏刷新率的问题**：ST7735S 刷一屏只要 16.7ms，
比摄像头一帧快十几倍。真正的瓶颈一直是**摄像头自己的帧时间**。

### 2. 帧率的总开关：`OV2640_CLKRC`（默认 `0x80`）

OV2640 **内部没有 PLL**，帧率只由一个寄存器决定 —— 传感器组(`0xFF=0x01`)的 `CLKRC(0x11)`：

```
CLK（内部主时钟） = XVCLK(模块上的 24MHz 晶振) × (bit7 ? 2 : 1) ÷ (bit[5:0] + 1)
帧率              = CLK ÷ (tLINE × 每帧总行数)
                    本机是 UXGA 栅格: tLINE = 1922, 每帧约 1560 行(含消隐)
```

WCH 原始例程写的是 `0x01` → `24MHz ÷ 2 = 12MHz` → **只有约 4fps**，
这就是"人动一下、画面要等半天才跟上"的根源（和曝光值、和 PCLK 都无关，
所以之前调 AEC 8/16/32 和 PCLK 4/1 都看不到 fps 变化）。

```c
/* main.c */
#define OV2640_CLKRC   0x80
```

| `OV2640_CLKRC` | CLK | 理论帧率 | 说明 |
|---|---|---|---|
| `0x01` | 12 MHz | ≈ 4 fps | WCH 原样（慢，仅作回退用） |
| `0x00` | 24 MHz | ≈ 8 fps | 稳妥的中间档：**画面花了就用这个** |
| **`0x80`（默认）** | **48 MHz** | **≈ 16 fps** | 数据手册标称工作点（XVCLK 24MHz + 2 倍频），最快 |

配套的两件事代码里已经自动处理：

* **曝光自动补偿**：帧率快 N 倍 → 同样的曝光值只有 1/N 的曝光时间 → 画面会暗 N 倍。
  所以真正写进摄像头的曝光值 = `OV2640_AEC_VALUE × 时钟倍数`
  （默认 `16 × 4 = 64`，曝光时间 64 行 × 40µs ≈ 2.6ms，和原来 `16 × 160µs` 一样，
  亮度基本不变）。
* **输出时钟自动跟随**：`OV2640_PCLK_DIV` 默认 = 时钟倍数，让
  `PCLK = CLK ÷ 分频` 恒等于 **12MHz**（现在验证过没问题的值），
  换了 `OV2640_CLKRC` 不用再手改这一项。

**回退办法（画面花/不出图/黑屏）**：把 `OV2640_CLKRC` 改成 `0x00` 重新下载；
还不行就改回 `0x01`（回到已知可用的 4fps）。诊断页 `clkXX` 能看出当前用的是哪一档。

### 3. 其它帧率/延迟相关参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `OV2640_LOW_LATENCY` | 1 | 关掉自动曝光，用固定曝光+手动增益；改 0 = 原厂自动曝光（暗处延迟几百毫秒） |
| `OV2640_AEC_VALUE` | 16 | 固定曝光值（会乘时钟倍数后写入）；**越小延迟越低、画面越暗** |
| `OV2640_GAIN_VALUE` | 0xCF | 手动增益；太暗加大（0xFF），发白减小（0x80/0x40）；填 0 = 增益自动 |
| `OV2640_PCLK_DIV` | =时钟倍数 | 摄像头输出 PCLK = CLK ÷ 本值；默认让 PCLK 恒为 12MHz，调大更稳、调小更快但可能花屏 |
| `LCD_SPI_PRESCALER`(`lcd.h`) | 24MHz | 推屏速度；出现花屏/错位就换 `SPI_BaudRatePrescaler_4`(12MHz) |
| `SLICE_ROWS` | 10 | 每片行数；调小=延迟更低(片更细)，调大=更省主循环开销 |

> 亮度和延迟是同一枚硬币的两面：曝光长→亮但慢，曝光短→快但暗（用增益补，代价是噪点）。
> 诊断页的 `fps` 就是延迟的晴雨表：**fps 翻倍 = 延迟减半**。

## 六、画面显示开关（旋转 / 左右镜像 / 上下镜像 / 补色 / 红蓝互换）

全部在 **`lcd.h`** 里，都是**整屏级、零成本**的开关（只写面板寄存器 MADCTL/INVON，
不占 CPU、不影响帧率、不占 RAM），连诊断页文字和校准画面一起变：

```c
#define LCD_ROTATE      0    /* 旋转: 0 / 90 / 180 / 270 (度) */
#define LCD_MIRROR_H    0    /* 左右镜像: 0/1 */
#define LCD_MIRROR_V    0    /* 上下镜像: 0/1 */
#define LCD_INVERT      0    /* 补色(整屏反相, 像底片): 0/1 */
#define LCD_BGR_SWAP    0    /* 红蓝互换: 0/1 */
```

| 开关 | 作用 | 什么时候用 |
|---|---|---|
| `LCD_ROTATE` | `0/180` 保持竖向 128×160；`90/270` 变成**横向 160×128** | 屏的安装方向不对时；**取图窗口、文字排版、分片缓冲都会自动跟着改** |
| `LCD_MIRROR_H` | 左右翻 | 摄像头/屏装反了 |
| `LCD_MIRROR_V` | 上下翻 | 同上 |
| `LCD_INVERT` | 整屏反相（白↔黑） | 画面像"底片"时（原来的 `LCD_USE_INVON` 仍然可用） |
| `LCD_BGR_SWAP` | 红蓝对调 | 红蓝互换时（等价于 MADCTL 的 0x08 位） |

**怎么用（典型组合）**

| 想要的效果 | 设置 |
|---|---|
| 正常竖屏 | 全部 `0`（默认） |
| 屏倒过来装 | `LCD_ROTATE 180` |
| 屏横过来装（左右转 90°） | `LCD_ROTATE 90`，若方向反了就用 `270` |
| 转完发现左右反了 | 用 `LCD_MIRROR_H`（转 90/270 后，H/V 的作用会互换，试另一个开关就行） |
| 只有摄像头画面要镜像、文字保持可读 | 用 `main.c` 的 `CAM_MIRROR_X`（不是这里的整屏开关） |

**注意事项**

* 旋转 90/270 时逻辑分辨率变成 160×128：取图窗口自动改成"中心 160×128"、
  诊断页行距自动收紧、分片缓冲自动变成 13 片（41.6KB，仍在 128K RAM 内）；
* 转 90/270 后如果画面整体偏 1~2 像素（边缘多出一条线），微调 `LCD_XSTART` / `LCD_YSTART`；
* 想直接写寄存器值（高级用法）：自己定义 `LCD_MADCTL` 就会覆盖上面 5 个开关；
* 诊断页最后一行会显示 `rot0 mh0 mv0 iv0 bgr0`，拍照给别人看时一眼就知道当前设置。

## 七、摄像头参数和屏幕匹配

摄像头输出 **240×320（3:4）**，屏是 **128×160（4:5）**，比例不同，两种处理方式：

```c
#define CAM_FULL_VIEW   0     /* 0 = 中心 1:1 裁剪(默认)   1 = 全视野 2:1 降采样 */
```

| 模式 | 看到的范围 | 画质 | 帧率/RAM |
|---|---|---|---|
| **0（默认）中心 1:1 裁剪** | 摄像头视野正中间那一块（约整幅的 1/4 面积） | **最好**：一个摄像头像素 = 一个屏像素，不缩放、最锐 | 不变 |
| **1 全视野降采样** | 摄像头**全部**视野，一点不裁 | 变糊/有锯齿（最近邻取样，横向 240→128 是 1.875:1 的非整数缩放） | 不变 |

* 两种模式都**不花 CPU、不影响帧率**（只是取像素的下标不同）。
* 模式 0 想换个位置看：`CROP_X` / `CROP_Y` 可以直接定义（单位 = 摄像头输出像素，0 = 最左/最上），
  例如只看左上角就在 `main.c` 里加两行：
  ```c
  #define CROP_X   0
  #define CROP_Y   0
  ```
* 想要"全视野 + 清楚"只能靠 OLED 更大分辨率或摄像头 ISP 输出 128×160，
  但后者之前试过没配对（见第八节 `OV2640_READOUT_OPT`）。

## 八、关键参数速查（出问题时先看这几个）

### 1. 像素字节序 `CAM_BYTE_SWAP`（默认 1）
OV2640 的 RGB565 是**低字节先发**（WCH 表里 `0xDA=0x09`），ST7735S 要求**高字节先发**，
所以必须交换一次。颜色变成另一种错法（红蓝互换/整体偏色）时可以改成 0 对比。

### 2. 画面左右镜像 `CAM_MIRROR_X`（默认 0）
`1` = 只镜像**摄像头画面**（诊断文字、校准画面不受影响）；实现上是在攒行时反向取样，
不额外花时间、不影响帧率。想让**整屏（含文字）**一起镜像：用 `lcd.h` 的 `LCD_MIRROR_H = 1`
（第六节；`LCD_MIRROR_V` = 上下翻）。

### 3. 传感器读出窗口实验 `OV2640_READOUT_OPT`（默认 0）

| `OPT` | 含义 | 结果 |
|---|---|---|
| **0（默认）** | WCH 原配置：输出 240×320 + 屏上取中心一块 | `r/f=320`、画面正常 ✅ |
| 1 | 读出窗口 + DSP 输入尺寸 + 输出 128×160 整套 | ❌ 实测 `r/f=14529`，设置没生效、画面会花 |
| 2 | 只改传感器读出窗口，DSP 与输出尺寸保持原样 | 未测（现在不需要了：帧率已由 `OV2640_CLKRC` 解决） |

相关：`OV2640_READOUT_W/H`（默认 424/300，宽 16 的倍数、高 8 的倍数）。
**结论：改读出窗口对帧率没用** —— 帧率只由栅格模式(COM7)和 `CLKRC` 决定，
读出窗口只影响"看哪一块"。

### 4. 画面显示开关
旋转/左右镜像/上下镜像/补色/红蓝互换都在 `lcd.h`，见第六节。

### 5. 显示时长
`CALIB_SHOW_MS`（校准画面，默认 2000）、`DIAG_SHOW_MS`（诊断页，默认 6000），填 0 跳过。

## 十、改动记录（相对 WCH 原 DVP_TFTLCD 例程）

原例程是 **ILI9341(240x320) + FSMC 16 位并口**，本工程改成 **ST7735S(128x160) + SPI**：

| 文件 | 改动 |
|---|---|
| `User/lcd.c` / `lcd.h` | 全部重写：SPI2 主机 + ST7735S 初始化 + 窗口/画字符 + **分片 DMA 刷屏** `LCD_PushBlock()` + 字节序交换；画面开关（旋转/镜像/补色/红蓝互换）自动换算 MADCTL/INVON，旋转 90/270 时逻辑分辨率自动变 160×128 |
| `User/main.c` | 重写数据通路：DVP 收行 → 取样/换字节序 → **分片缓冲(每片 10 行，最后一片可不满)** → 立刻 DMA 推屏；新增校准画面与诊断页（排版按屏高自适应）；新增 `OV2640_CLKRC` 帧率开关、`CAM_FULL_VIEW` 视野开关 |
| `User/ov.c` / `ov.h` | 新增 `OV2640_OutSize_Set2()` / `OV2640_SetReadout()` / `OV2640_Config()` / `OV2640_LowLatency()` |
| `Ld/Link.ld` | **工程专用链接脚本**：RAM 32K → **128K**；不再链接共用的 `SRC/Ld/Link.ld` |
| `.project` | 取消 `Ld` 的链接引用（改用工程目录下的 `Ld/`） |
| `.cproject` | 增加预处理宏 `DEBUG=DEBUG_UART2`（UART1 被 DVP 占用） |

> 历史备注（调试中确认过的结论，供以后参考）：
> ① 传感器内置八色彩条可用 `传感器组(0xFF=0x01)` 的 `COM7(0x12)` bit1 打开（判断摄像头好坏）；
> ② 行缓冲要读"另一个"缓冲区（不能读写正在写的那个）；
> ③ 小尺寸输出必须配合 ISP 降采样档位；
> ④ 摄像头送的是低字节先发，屏要高字节先发，**必须换**；
> ⑤ 帧率只由栅格模式(COM7) + `CLKRC` 决定，**与读出窗口、曝光值、PCLK 无关**；
> ⑥ 屏 60Hz 不是延迟瓶颈，摄像头帧时间才是；
> ⑦ **取样步长必须按"这一屏行横跨多少源像素"算**：中心裁剪模式横跨 128 个源像素(1:1, step=256)，
>    全视野模式横跨 240 个(step=480)。如果一律按整幅宽算，中心裁剪就会变成"整幅压缩到屏上"，
>    而且取样下标会冲出 480 字节的行缓冲 —— 现象是**画面出现竖条纹 + 屏右侧约 1/4 一条固定花边**
>    （花边内容不随画面/时钟变化，因为它读的是行缓冲后面那块内存）。
